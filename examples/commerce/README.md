# 电商合成样本

这两份文件为项目自行编写的合成记录，不包含真实客户或真实订单。

先以 JSON 来源导入 `orders.with-issues.json`，采集时间填这份样本的已知时间，
唯一标识设为 `order_id`。检查会发现重复订单、缺失客户标识和金额类型混用。
不要为了让结果通过而把实际采集时间改成今天；日期过旧本身也可以是需核实的问题。

接手重复订单任务后，使用“更新快照”上传 `orders.corrected.json`，填写更晚的
实际采集时间，再重新盘点。完整样本中重复规则不再触发后，可用另一个本地演示
身份测试核验路径。这个演练只验证软件流程，不代表真实企业问题已经解决。

修正文件有意合并了重复订单，同时保留全部不同订单标识。真实修复还应核对原始
系统记录与业务规则，不能通过删除有问题的业务对象来假装数据改善。
