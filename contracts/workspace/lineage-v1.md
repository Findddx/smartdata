# 数据血缘接口 v1

血缘图说明“有什么来源、登记了什么关系、还不知道什么”。它不执行 SQL，不提取
客户实体，也不计算业务指标。独立合成实验的已生成产物不会自动进入用户工作区。

| 接口 | 权限与行为 |
|---|---|
| `GET /api/v1/workspace/lineage` | 当前租户、授权来源与业务范围的图投影；返回 `LineageGraph` |
| `GET /api/v1/workspace/lineage/sources/{sourceId}/assets/{assetId}/fields?offset=0&limit=128` | 同租户、可见范围和当前成功盘点下的单表字段元数据分页；返回字段 Node 与真实 TABLE→FIELD 关系 |
| `GET /api/v1/workspace/lineage/mappings` | 仅管理员；读取当前来源映射及其版本 |
| `POST /api/v1/workspace/lineage/mappings` | 仅管理员；必须有 `Idempotency-Key`、工作区预期版本和映射预期版本；返回 `WorkspaceView` |

POST 后按新工作区版本重新读取图。工作区与映射版本不匹配均拒绝，不覆盖并发修改。
本接口目前只在显式 `local` 部署下开放；演示角色不能被解释为真实企业身份认证。

- L0：原始来源、表/数据集、字段。只有当前成功盘点的包含关系使用实线。
- L1：人工明确输入字段的业务实体定义，虚线，`NOT_MATERIALIZED`（未生成实体记录）。
- L2：直接引用业务约定中的指标编号及口径版本；虚线，未计算。来源说明不能冒充已执行公式。
- L3：业务目标与明确指标输入组成的决策计划；点线，未执行，也不代表业务目标已达成。

所有边方向为 `from` 输入/所属容器 → `to` 结果/所含对象。`CONTAINS` 表示物理包含，
`MAPPED_TO` 表示登记的字段到实体映射，`FEEDS_INTO` 表示输入支持指标，`INFORMS`
表示指标被计划用于决策；不用方向容易读反的“派生自”命名。

形状表示对象类型，颜色由界面稳定映射层级。敏感级别、新鲜度、授权与业务范围是
独立属性。没有登记敏感级别时显示 `UNKNOWN`；不会根据“email”等字段名称猜测。
`METADATA_VISIBLE`只表示当前身份可看工作区元数据，不代表源系统读写或执行权限，
也不证明来源凭据已经验证。
当前没有采集源系统的 SQL 和作业变换，因此源系统字段转换一律明确未知。

重配或盘点失败的来源只显示登记节点，不展示历史字段为当前观察；已断开的来源
不进入图。任何依赖越界或断开来源的派生定义整体隐藏。USER 与 DEMO 来源不能
混入一个派生定义。映射依赖类型只允许 L0→L1/L2、L1→L2、L2→L3；不能表达反向或循环依赖。

映射实体编号使用 `[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`。实体名称最多100字符，类型说明
80字符，处理说明2000字符；字段引用最多100个，实体必须有输入。最多保存50个实体、
40项指标来源和12项决策来源。指标必须引用已有 `metricId` 与当前 `definitionVersion`。
仅保存处理说明，不把用户文字作为 SQL、脚本或模型提示词执行。历史保留50版，超过时
明确拒绝继续写入。整包最多512项字段引用、256项实体输入和128项决策指标输入。

默认图最多3000节点、6000条边，字段按来源/表/字段名稳定顺序展示最多256个。
`coverage` 显示已展示/已登记的来源、表、字段数量与因依赖不完整而隐藏的派生定义数，
覆盖不全时 `partial=true` 并给出说明。缺少节点或连线不能被当成没有影响；派生输入
没有完整展示时，整条派生链不画成完整血缘。覆盖统计仅针对本轮可见的已登记元数据，
不代表企业全量业务数据覆盖。

单表分页每次1–128个字段，返回 `stateVersion/sourceId/assetId/totalFields/offset/limit/
nodes/edges/hasMore`。客户端须检查工作区版本一致，变更后刷新；不跨版本拼接字段。
映射写入直接校验真实元数据，不因默认图的展示预算而拒绝合法的未展示字段。

响应定义见 [JSON Schema](lineage-v1.schema.json)。完整输入 DTO 见
`LineageModels.kt` 的 `SaveLineageMappingsCommand`；所有列表拒绝 null 元素。
