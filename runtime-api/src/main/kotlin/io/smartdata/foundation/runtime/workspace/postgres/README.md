# 共享工作区数据库适配

这个适配器让同一企业的当前有效成员共享来源、扫描、任务、评论和历史记录。它与履约内核使用同一个基座元数据数据库和短事务设施，业务表相互独立；不能把它连接到客户ERP数据库作为保存位置。

构造方式：`PostgresWorkspaceStore(PostgresUnitOfWork, WorkspaceTransactionAccessPort, Clock)`，模式为 `POSTGRES_SHARED`。根配置显式提供企业成员检查器、仅上传JSON的连接器和规则解释器；没有文件存储、模拟身份或模型自动降级的生产替代方案。

`readAuthorized(actor)` 和 `mutateAuthorized(actor, expectedVersion, key, fingerprint, lease?, mutation)` 在同一数据库事务中检查当前成员状态、角色集合和授权版本。修改期间成员行的共享锁一直保留到提交；撤权通过更新该成员行与版本完成。没有认证成员的旧 `read(tenantId)` / `mutate(tenantId,...)` 在数据库模式中直接拒绝。本地文件实现保留原接口和原数据，不自动导入。

V4新增25张工作区关系表。来源与来源版本、独立快照正文、扫描、资产版本、字段、发现、助手、任务及其版本、评论、消息、审计、命令、运行登记、业务约定及口径、来源映射及输入分别保存。当前指针可以前进；历史版本不能覆盖或删除。原始快照正文限1MiB，独立受租户行权限保护；这不是已经接入对象存储，也不是大数据正文存储方案。正文不进入公共视图、审计或事件。

工作区版本、关联数据、命令去重、审计和待发送事件一起提交。重试只保存过的命令时，重新检查当前权限并返回当前投影，不缓存旧的敏感HTTP响应。当前仍保留v1的全工作区版本比较：两个无关评论也可能冲突，不能宣称自动合并或多租户容量目标已经达成。兼容视图和历史均有明确上限，达到上限会拒绝继续写入，不会静默丢弃或覆盖。

扫描或解释先调用 `reserveExternalOperation`，保存操作与60秒租约后释放数据库事务，才运行来源/模型代码。相同操作处理中不重复启动；提交时必须匹配身份、授权版本、命令摘要和租约令牌。过期、进程崩溃或无法确定结果时记为/视为 `UNKNOWN`，不会自动重试可能已收费的调用。结果未知时需要后续受控对账或由用户明确发起新命令；首版没有伪装成自动恢复的调度器。首发企业配置只使用规则解释，没有模型费用，也不进行持续同步。

所有新表加入强制租户隔离与运行角色启动检查。不可变表另有数据库触发器拒绝改写，任务版本具有“完成人与复核人必须不同账号”的检查。账号不同不独立证明是两个自然人，仍需要企业管理账号归属。生产写入源系统的能力继续关闭。

真实数据库验收代码位于 `PostgresWorkspaceIntegrationTest`，覆盖双账号交接、新快照复核、历史恢复、并发冲突、持久去重、运行租约、撤权晚到、整体回滚、原始正文隔离。编译与普通单测不能代替该套真实PostgreSQL测试；实际通过与否以本轮验收记录为准。
