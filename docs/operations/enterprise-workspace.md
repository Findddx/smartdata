# 企业登录与多人工作区上手

这条路径让真实员工使用企业账号进入同一个工作区，按当前成员权限处理有证据的任务。
它与本机演示模式分开：企业工作区使用 PostgreSQL 保存资料与登录状态，不能通过修改
浏览器里的角色名称获得管理员权限。

本文件说明当前代码提供的配置和操作路径，不把“配置已写好”当作部署已经验收。
实际运行结果见[验收记录](../verification)；整体进展见[项目总纲](../../PROJECT_CHARTER.md)。
目前仍需授权运维人员准备账号系统、数据库和证书，尚未做到普通用户下载后完全零运维。

## 当前适用范围

一个部署对应一家企业，企业编号由服务端固定配置。页面没有让用户填写企业编号来
切换数据的入口，也不根据公司名称、姓名或邮箱猜测谁属于这家企业。

本轮企业模式提供：真实登录、精确账号邀请、角色管理、暂停与恢复成员、共享工作记录、
JSON 快照盘点、规则发现、业务约定、来源声明图谱，以及处理人与另一名复核人的交接。
来源只接受已获准使用的用户 JSON 快照（内部标记为 `USER`）；助手按固定规则整理证据。远程业务 API、
数据库探测、模型解释、自动持续监测及履约写操作，不在本轮企业模式的开放范围内。
图谱里的实体、指标与计划仍须区分“已登记定义”和“已经生成或核实的结果”。

## 部署负责人先准备什么

OIDC 是复用企业账号登录的标准协议；IdP 是实际检查员工账号、密码和多重验证的身份服务。
SmartData 使用登录结果识别人，不接收员工在账号系统中的密码。

1. 在可信的企业 IdP 注册一个需要客户端密钥的应用，使用授权码登录，开放 `openid`、
   `profile` 范围。身份服务及其发现的授权、令牌和公钥地址必须使用受信任的 HTTPS。
2. 为工作区确定一个固定 HTTPS 根地址，例如 `https://smartdata.example.com`，不附加路径、
   查询参数或片段。在 IdP 精确登记回调地址：
   `https://smartdata.example.com/login/oauth2/code/enterprise`。登录时会使用 PKCE，即把这次
   登录请求与回调换取结果的过程绑定；不能把任何请求传来的 Host 当成新的回调地址。
3. 准备与该地址相符、浏览器信任的 HTTPS 证书及 PKCS12 文件。PKCS12 是把证书和私钥
   封装在一起的文件，需要单独保护其密码。证书别名和域名须按实际部署设置。
4. 由数据库管理员准备 SmartData 专用数据库和三个不同用途的账号：受控迁移账号、
   业务运行账号、会话运行账号。数据库账号与页面上的“业务负责人”等产品角色是两回事。

业务与会话运行账号必须是专用的小写登录角色，不能是超级用户、表所有者，也不能绕过
行权限、创建数据库或角色、建表，或通过所属角色取得这些能力。数据库管理员应通过
安全渠道设置密码，不在公开 SQL、命令参数、Git 文件或普通日志中写密码明文。

首版配置在同一个专用库中分出业务表与 `smartdata_session` 会话区，用两个不同账号连接。
业务账号不能读取会话表，会话账号不能读取业务表。远程数据库地址必须带
`sslmode=verify-full`：既加密连接，也校验证书与主机名。

## 先准备数据库，再启动网页服务

数据库准备入口为：

```bash
./gradlew :runtime-api:prepareEnterpriseDatabase
```

Windows 使用 `./gradlew.bat`。该命令不启动网页服务；它执行版本化迁移、检查版本，
登记固定企业，并向预先建立的两个运行账号授予本工作区所需的最小权限。
只在 SmartData 专用库运行；准备过程会调整 `public` 的建表权限，不能对公司现有业务库使用。

在独立的运维 shell 或迁移作业中安全注入以下变量：

| 变量 | 用途 |
|---|---|
| `SMARTDATA_SETUP_DB_URL` | 专用库的 JDBC 地址；远程使用 `verify-full` |
| `SMARTDATA_SETUP_DB_USER`、`SMARTDATA_SETUP_DB_PASSWORD` | 本次受控迁移账号 |
| `SMARTDATA_DB_USER` | 预先建好的业务运行角色名称 |
| `SMARTDATA_SESSION_DB_USER` | 预先建好的会话运行角色名称，必须与业务账号不同 |
| `SMARTDATA_ENTERPRISE_TENANT_ID`、`SMARTDATA_ENTERPRISE_NAME` | 本部署固定企业编号与显示名称 |

角色已有额外权限时，该入口会拒绝继续，不会擅自撤销其他服务的权限；应由数据库管理员
检查或另建专用角色。已有企业的名称或状态与本次准备不一致时，也不会静默覆盖。
数据库准备成功只说明这一步完成，网页服务还须单独通过启动与健康检查。

网页进程不能接收 `SMARTDATA_SETUP_DB_*` 迁移凭据。企业配置关闭运行时 Flyway 自动迁移，
也不允许服务自动创建会话表；缺少表、权限或必要组件时应停止启动，不能切换成文件演示。

## 网页服务的私有配置

实际变量映射以 [application-enterprise.yml](../../runtime-api/src/main/resources/application-enterprise.yml)
为准；以下内容由部署负责人通过受控环境或密钥管理工具提供。

| 变量 | 配置内容 |
|---|---|
| `SMARTDATA_DB_URL`、`SMARTDATA_DB_USER`、`SMARTDATA_DB_PASSWORD` | 专用库地址及业务运行凭据 |
| `SMARTDATA_SESSION_DB_USER`、`SMARTDATA_SESSION_DB_PASSWORD` | 同库的独立会话运行凭据 |
| `SMARTDATA_ENTERPRISE_TENANT_ID`、`SMARTDATA_ENTERPRISE_NAME` | 与数据库准备时一致的企业编号和名称 |
| `SMARTDATA_OIDC_ISSUER` | IdP 的精确签发方地址，保留其实际路径与尾斜杠约定 |
| `SMARTDATA_OIDC_CLIENT_ID`、`SMARTDATA_OIDC_CLIENT_SECRET` | 已注册应用的编号与密钥 |
| `SMARTDATA_EXTERNAL_BASE_URL` | 前述固定 HTTPS 工作区根地址 |
| `SMARTDATA_API_AUDIENCE` | 面向本服务的访问令牌接收方；默认 `smartdata-runtime` |
| `SMARTDATA_ENTERPRISE_BOOTSTRAP_OWNERS` | 首批负责人的精确账号编号，逗号分隔，可先留空 |
| `SMARTDATA_SESSION_ENCRYPTION_KEY` | 32 字节密码学随机值，经 Base64 转为配置文本 |
| `SMARTDATA_TLS_KEYSTORE`、`SMARTDATA_TLS_KEYSTORE_PASSWORD` | PKCS12 文件位置与受控密码 |
| `SMARTDATA_TLS_KEY_ALIAS` | 文件中的证书别名；默认 `localhost`，部署时按实际设置 |
| `SMARTDATA_BIND_ADDRESS`、`SMARTDATA_PORT` | 默认仅监听 `127.0.0.1:8080`，由运维决定外部接入方式 |

会话是服务端保存的登录状态。会话内容采用带篡改检查的加密保存，浏览器只持有受保护的
会话 Cookie；前端不把登录令牌放入本地存储。所有实例与正常重启须保留同一会话加密密钥，
不能每次启动重新生成。更换密钥前安排重新登录；旧会话不能靠猜测或降级格式恢复。

构建一个带工作台的服务包时，先使用已锁定的前端依赖生成 `console/dist`，再打包：

```bash
cd console
npm ci --ignore-scripts
npm run build
cd ..
./gradlew :runtime-api:bootJar -PbundleConsole=true
```

在已安全注入上述运行变量的环境启动服务包，显式选择企业和 PostgreSQL 配置：

```bash
java -jar runtime-api/build/libs/runtime-api-0.1.0-SNAPSHOT.jar --spring.profiles.active=enterprise,postgres
```

默认绑定回环地址；远程员工使用的固定 HTTPS 域名必须由运维正确接入该服务。
页面、登录回调和 API 使用同一来源。不要用本机 HTTP 演示入口替代企业 HTTPS 配置。

## 第一位负责人怎样开通

系统使用经过验证的 `issuer` 与 `sub` 生成稳定的 `acct_…` 账号编号。前者是账号服务的
固定标识地址，后者是这个服务内稳定的个人编号。姓名和邮箱相同，不会自动变成同一个人。

1. 初始负责人白名单可以先留空。准备并启动企业服务后，拟任负责人点击“使用企业账号登录”。
2. 登录成功但尚无成员资格时，页面只显示自己的账号编号和等待加入状态，不返回企业工作资料。
3. 负责人复制账号编号，由授权运维通过可信渠道核对本人和所属企业，再将该精确编号加入
   `SMARTDATA_ENTERPRISE_BOOTSTRAP_OWNERS`，重启服务。
4. 该账号退出 SmartData 后重新发起企业登录，经过新的 OIDC 回调。仅刷新页面或 `/me`
   不会执行初始负责人授权。
5. 首次创建成员记录时，白名单账号获得管理员角色并留下审计记录。之后从“企业成员”管理协作。

白名单只是一次初始开通依据，不是永久管理员修复器：已有成员被暂停或改了角色后，
再次登录、重启服务都不会用白名单把权限偷偷恢复。反过来，删掉白名单也不会自动撤回
已经授出的成员权限；撤权须在成员目录中执行。

## 普通同事的使用步骤

1. 打开企业 HTTPS 地址并登录。未加入时，将自己的账号编号交给负责人。
2. 负责人打开“企业成员”，粘贴精确账号编号，选择职责并登记邀请。系统不接受用姓名或邮箱
   猜测目标，也没有让同事自行选择管理员的入口。邀请有效期为七天。
3. 同事重新检查加入状态，核对显示的角色后接受指定给自己的邀请。别人的、过期的、
   被撤销的邀请不能拿来加入。邀请人的权限若已变化，应请负责人重新登记。
4. 管理员导入已获准使用的脱敏 JSON 快照，填写实际采集时间，完成盘点。记录上限、
   完整性与证据以界面实际返回为准，不能把一份文件当作整个企业已检查。
5. 填写业务目标与指标口径，按实际发现组建三类助手，成员认领问题、补充讨论和提交处理说明。
   口径文字并不执行计算，任务“完成”也不代表问题已经消失。
6. 来源修正后，上传实际更新的完整快照并重新盘点。另一名具备复核权限的真实成员核验新观察；
   同一个人切换业务角色仍不能充当第二个人，不完整采样也不能冒充完整修复证明。

并发保存发生版本冲突时，先看最新记录，再明确重载或重新核对，不能反复点击覆盖同事。
请求超时、结果不明时先刷新成员、邀请或工作记录确认结果，不盲目重试。

快照上的“已复核”只证明上传观察范围通过了对应规则，不证明外部店铺或仓库系统已经
修复。企业还须确认账号背后的人员与岗位归属，再在真实试点中验收双人协作流程。

## 权限变化、退出与账号停用

当前权限取自企业成员目录，不取自浏览器填写的角色，也不把旧令牌里的角色当成永久授权。
成员修改时会同时核对目录版本与目标成员版本，工作区操作在事务提交前再次检查权限。
正在进行的工作与撤权按服务端提交顺序判定，暂停不抹去先前合法完成的历史。

管理员可暂停成员、恢复成员、修改角色或撤销尚未接受的邀请。系统阻止自己暂停自己、
移除最后一名可用管理员等不允许的操作。恢复成员不恢复旧邀请或过去的批准。
权限服务或会话读取失败时，页面应先停止工作台访问，不能把旧资料继续显示成当前可操作状态。

点击“退出企业账号”会删除 SmartData 的共享会话。默认闲置三十分钟、或登录满八小时后也
需要重新登录。这不同于退出整个企业账号系统：IdP 可能保留自己的单点登录状态。
本轮没有接入 IdP 的即时停用通知；只在 IdP 后台停用员工，不能当作已立即撤销 SmartData
现存会话的证明。紧急离职或撤权时，还应在 SmartData 暂停该成员。

## 常见停在半路的情况

| 现象 | 应核对什么 |
|---|---|
| 登录按钮后失败或返回地址错误 | 固定 HTTPS 根地址、精确回调、IdP 注册信息、证书信任与域名 |
| 登录成功仍等待加入 | 负责人是否登记了这个精确账号；首位负责人是否在白名单变更后重新完整登录 |
| 邀请可见但不能接受 | 目标账号、有效期、邀请版本、邀请人当前权限；暂停成员须由管理员恢复 |
| 返回 401 | 登录未完成、会话到期或无效；重新登录，不手填访问角色 |
| 返回 403 | 当前成员权限、安全校验或授权版本不允许；刷新身份并联系负责人核对 |
| 返回 409 | 同事或另一个窗口已经改变记录；保留草稿，核对新版本后再操作 |
| 服务启动失败 | 迁移是否完成、运行账号是否独立且权限最小、密钥长度、HTTPS 与数据库证书配置 |

这些步骤把身份与协作的第一条企业路径接起来；真实 IdP、最小数据库权限、恢复演练及
业务试点仍需按各自证据验收，不能据此宣称已达到生产容量或自动优化全公司数据平台。
