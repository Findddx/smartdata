# 从空工作区开始

通用工作区在本机运行，保存来源、诊断和协作记录。它能连接真实的只读来源，
默认助手使用检查规则整理结果；可由管理员[显式启用模型解释](model-reasoning.md)，
保留依据、未知项与版本记录。企业登录、持续监测、自治团队和生产部署
仍按[路线图](../roadmap.md)推进。

## 启动与停止

Windows 安装 JDK 25、Node.js 24+、Git 后，在项目目录运行：

```powershell
.\scripts\start-local.ps1
```

脚本构建服务、安装前端依赖，并打开 `http://127.0.0.1:5173`。首次准备需要联网。
已构建过且没有修改后端代码时，可使用 `-SkipBuild`。端口占用时可以指定
`-ApiPort 18080 -ConsolePort 15173`。脚本不会结束占用端口的其他程序。

```powershell
.\scripts\stop-local.ps1
```

数据保存在 `.local/workspace`，停止后仍保留。该目录及原始思考材料不进入公开
Git 仓库。请把它放在自己的私有本地磁盘，不要放进多人共享或云盘同步目录。

## 体验与接入

第一次进入会看到空工作区。点击“先体验电商示例”，可运行订单重复、字段缺失和
库存过期等合成样本。每项发现都来自实际检查，标注为演示，不是企业真实结果。
“数据连接 → 退出演示工作区”只移除演示记录，然后可以接入自己的来源。

最直接的接入方式是 JSON 数组：

```json
[
  {"order_id":"A-1","amount":128,"updated_at":"2026-10-25T08:00:00Z"},
  {"order_id":"A-2","amount":256,"updated_at":"2026-10-25T09:00:00Z"}
]
```

最多 1,000 行、平面字段；嵌套对象请先整理为业务视图。表单要求填写实际采集
时间，并可指定唯一标识、更新时间字段和可接受的延迟。不要把上传时刻冒充采集
时刻。打开“数据资产”能看到本次读取的字段和范围，不会返回原始记录正文。

业务 API 和 PostgreSQL 连接还需要服务端运维人员配置明确的目标和凭据授权。
凭据表单只接受 `SMARTDATA_CONNECTOR_` 开头的环境变量名字，不接收密码正文。
远程连接要求 TLS（加密并验证服务端身份）；本地明文例外仅限字面 `127.0.0.1`。
精确配置和 API 契约见 [Workspace 协议](../../contracts/README.md)。不要用管理员
数据库账号；只授予目标业务表或视图的读取权限。

## 让协作闭环

1. 打开诊断发现，核对实际观测、规则、证据和样本范围。
2. 在“服务团队”按发现分工，选择运维、分析或决策助手，查看它引用的任务。
3. 在任务内写说明、接手、保存讨论，再提交处理结果。通用工作区不修改来源系统。
4. 修正来源后重新盘点。JSON 来源可通过“更新快照”上传修正后的记录和实际采集时间。
5. 由另一个本地演示身份复核最新盘点。完整观测下原规则不再触发才可能核验；
   采样不稳定、总量未知、原字段消失、只有旧证据，都不能认定修复。

左下角的身份切换用于本地功能演练，不是企业登录，也不能证明真实的双人审查。
生产身份必须接入企业登录和授权服务后单独验收。

## 怎样理解结果

“规则未发现问题”只说明本次输入和已配置规则没有命中。它不证明全库健康、不证明
业务因果、不代表持续在线，也不意味着模型已经了解企业。服务断开或 API 失败会
保留旧记录并明确报错，不会悄悄用演示数据替换。“导出报告”生成可直接阅读的中文
文本；结构化 JSON 仍由 `/api/v1/workspace/report` 提供，便于系统集成。
