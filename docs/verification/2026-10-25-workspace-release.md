真实 HTTP 演练使用全新的临时目录，只上传两条明确命名的合成订单。步骤为：
发现重复键和缺值 → 建立三类职责助手 → 提问、领取、评论和提交任务 →
拒绝使用旧证据自证修复 → 上传更新且已更正的完整快照 → 重新盘点 →
换用另一位本地演示身份复核 → 读取工作报告。随后停止服务，再用同一目录重启并核对记录。
最终工作区版本为 10。脚本不会清空用户工作区，也不把演示身份当成真实双人审批证明。

浏览器检查还使用了此前旧规则版本保存的演示工作区；最新服务能读取原来源、历史
发现、任务和消息，新字段以兼容默认值补齐。可复用浏览器脚本及适用前提见
[浏览器验收说明](../../console/e2e/README.md)。截图只来自合成演示，不含客户原始记录。

对应的可复用命令如下。运行 HTTP 演练前必须按[契约说明](../../contracts/README.md)
启动一个专门用于测试的空工作区；模型保持本地规则模式，不会读取 API Key 或调用供应商。

```powershell
.\gradlew.bat --no-daemon --no-parallel --max-workers=1 test cyclonedxBom --write-locks
.\gradlew.bat --no-daemon --no-parallel --max-workers=1 :runtime-api:bootJar
npm run validate --prefix contracts
npm run smoke:workspace --prefix contracts
# 停止服务，再用相同测试存储目录启动后：
npm run smoke:workspace --prefix contracts -- --verify-restored
```

本机实际使用 Temurin JDK 25.0.2+10、Gradle 9.3.0、Node 24.18.0；代码编译目标为
Java 21。CI 配置另固定 Temurin 25.0.4.1+1 和 Node 24.8.0，本报告不把 CI 的目标版本
写成本机已经执行的版本。

## 新增依赖怎样核对

新增 Spring AI 模型入口需要同时更新依赖锁和可信文件指纹。
SHA-256 可以理解为文件指纹：它检查当前文件是否与核对过的原件相同，不能证明软件没有漏洞。

本轮先生成候选清单，再从 Maven Central 官方 HTTPS 地址逐个下载原件比对。
**70 个新增文件全部匹配，原有 842 个可信指纹全部保留。**
每个文件的坐标、官方地址、实际指纹和直接声明的许可证保存在
[逐项核验清单](2026-10-25-model-dependencies.json)。校验过程没有关闭依赖验证，
随后不带“生成校验值”参数的严格构建通过了全部模块测试和可运行包构建。

37 份新增 POM（依赖自身的说明文件）中，27 份直接声明许可证；其余 10 份逐一核对到
本次清单中已验证的父说明文件。victools 和 Swagger 的父声明为 Apache 2.0，
ANTLR 的父声明为 BSD。新增直接或上述继承声明中没有 AGPL/SSPL；这不是法律认证，
也没有代替未来版本的许可证和漏洞复核。

[增量校验脚本](../../scripts/verify-maven-additions.ps1)可以重复使用，输入更新前后的
校验文件并指定输出报告。它拒绝更换或删除旧可信指纹，且只从固定的官方地址下载、
不跟随重定向。已用不变、删除和替换指纹三种样例实际检查拒绝行为。

应用的数据格式库仍是 Jackson 3.2.1。官方 OpenAI SDK 内部需要另一套包名的
Jackson 2.21.5，两者保留各自用途；没有强行替换 SDK 的类。CI 从实际物料清单检查
全部 `tools.jackson` 组件与版本目录一致，防止应用一侧混版；本次五个相关组件均为 3.2.1。
具体边界见[模型接入说明](../operations/model-reasoning.md)。
