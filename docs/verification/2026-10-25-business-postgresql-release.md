# 业务约定与真实 PostgreSQL 验收记录

本轮补上两项基础能力：业务约定让负责人说明目标与指标定义；履约仓储让案件、审批和
执行记录进入真实数据库。前者避免助手忙于检查却偏离经营目标；后者避免应用重启后
丢失已批准的动作或误把未知结果当成成功。

通用工作区和业务约定仍使用本地文件保存；生产 HTTP 装配与持久化去重尚未接通，
这两项能力目前没有合并成一个已生产接线的统一工作流。

这是本轮的增量验收记录。[前一阶段报告](2026-10-25-workspace-release.md)中的测试数量
和未完成项描述保留为当时证据，不用本轮结果改写历史。生产启动门继续保持关闭；
真实企业身份、真实连接器、完整权限服务、恢复演练和容量验收仍须分别通过。

  这些脚本没有拦截请求或替换后端响应；使用的都是明确标示的合成演示资料。

## 数据库验收状态

普通 JVM 测试实际执行 124 项，失败、错误和跳过均为 0。真实 PostgreSQL 测试使用独立任务，
不能用普通测试通过代替。本地 **20 项真实 PostgreSQL 18.6 检查全部通过**，失败、错误和
跳过均为 0；JUnit 报告明确记录 `PORTABLE_POSTGRES_18_6` 来源。远程强制 Testcontainers
作业待本轮提交后执行，当前没有把本地通过写成容器已通过。

本地没有可用 Docker，因此另建立了显式的 PostgreSQL 18.6 便携测试实例。
它只监听本机，不使用用户工作区；停止或中断前必须核对这个测试实例的目录、进程、
启动时间和集群编号。CI 仍必须使用真正的 Testcontainers，报告来源不符或测试被跳过都会失败。
完整检查范围见[数据库验收设计](postgresql-integration-plan.md)。

20 项实际覆盖新装与 V1 升级、低权限账号、数据库自身的租户隔离、连接复用、并发版本
冲突、整笔回滚、历史主张修订、证据与回执不可改写、动作真实意图冲突、命令结果账本、
审批执行与独立验证、模糊超时对账、事件租约，以及真实数据库进程中断后的恢复。
中断用例先刷盘无关测试数据，再提交本用例的新案件、审计与事件；立即停止数据库并
重新启动后，重新建立连接，确认这笔新提交完整保留。磁盘同步和完整页写入始终开启。
这是单机进程故障验证，不是灾备切换、磁盘损坏或整机断电验收。

真实数据库反馈还纠正了普通测试无法发现的问题：时间参数需要明确数据库类型；
可为空的版本号必须保留“未知”，不能被 Java 基础数字类型读成 0；相同动作指纹也必须
逐项比较真实输入，不能凭摘要相同就接受另一处置意图。没有降低断言或关闭数据库保护。
