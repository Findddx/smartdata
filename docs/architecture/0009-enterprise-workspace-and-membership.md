# 0009：把单机工作台接成真实企业协作

日期：2026-10-25。状态：已采用；节点上的核心协议与数据库验收通过，最终发布与范围见阶段汇报。

## 要解决的问题

现有界面能盘点数据、分派任务、评论和复核，但使用的是本机演示身份，工作区保存在
私有文件。已经验收的 PostgreSQL 仓储负责订单履约内核，并未保存这个通用工作区。
因此，不能把现状描述为“两名企业员工已经可以安全地共同使用”。

本阶段的完整故事是：负责人用企业账号登录，邀请另一账号加入；员工导入获准的
脱敏完整快照，认领并完成问题，另一名员工凭新观察复核。重启后记录还在，暂停的
成员即使持有旧会话，也不能继续访问。

## 决定

1. 浏览器通过 OIDC（企业身份服务的标准登录协议）证明“这个账号是谁”。采用授权码
   和 PKCE（防止登录码被截走后冒用的校验），令牌留在服务器。浏览器只持有受保护的
   会话 Cookie，所有变更请求同时防范跨站请求伪造。
2. 登录不自动授予企业权限。账号由签发方和账号编号共同标识；企业成员目录决定
   当前所属企业、角色和停用状态。首位负责人由部署方明确指定，邀请绑定准确账号，
   不能靠浏览器填写角色、企业编号或未经核实的邮箱获得权限。
3. 角色和停用状态每次请求重新检查，写入时在短事务内再查一次。长时间读取来源或
   调用模型不占用数据库锁；回来提交时仍须检查成员和记录版本。
4. 企业工作区存入独立的 PostgreSQL 行表。来源、扫描、任务、评论、审计和定义历史
   分开保存，不把全企业状态塞成一个大 JSON。快照正文与目录元数据分开，首期只
   接受有界完整快照；大规模原始数据的对象存储仍须另行接通和验收。
5. 数据库强制按企业隔离；迁移账号与运行账号分开。外部调用先留下持久的操作记录，
   再在事务外执行，防止多实例同时重复调用；结果不明时显示待核查，不盲目重试。
6. 本机演示模式保留，企业模式不得回退到演示身份、文件保存或仿真业务执行器。
   尚未完成生产装配的履约接口明确关闭，不能靠缺少组件偶然启动失败充当就绪检查。

初期保留接口现有的工作区版本检查：两人同时编辑可能需要刷新后重试，界面应保留
草稿。按独立任务自动合并并发编辑，属于后续扩展，不能提前宣称已经支持。

## 怎样验收

使用真实 PostgreSQL 和独立登录服务检查：真实双账号登录、精确邀请、跨企业拒绝、
旧会话撤权、自己不能复核自己的成果、并发不覆盖、重启恢复、重复请求不重复提交，
以及外部调用期间不持有数据库事务。浏览器检查须经过实际登录重定向，不能仅靠在
测试里塞入身份对象冒充完整登录验收。

生产能力是否可用，以实际启动、接口与浏览器证据为准。仅新增表、通过单元测试或
显示一个登录按钮，都不能独立证明本故事完成。

## `/me` 与 CSRF 请求头使用同一种遮罩规则

本产品从 `/me` 读取每次响应变化的 CSRF 校验值，再放入请求头。这个遮罩值用于
避免响应压缩泄露固定校验值，不能直接套用“从 Cookie 读取原值”的另一种客户端约定。
锁定的 Spring Security 7.1.1 中，`csrf.spa()` 默认向请求属性写入 XOR 遮罩值，
却按原值读取非空请求头。此前直接把属性值交给客户端，会使合法变更请求也被拒绝。

保留原有 Cookie 仓库，显式使用 `XorCsrfTokenRequestAttributeHandler`，统一解码
`/me` 返回的遮罩值；继续生成每次变化的遮罩，不关闭 CSRF，也不向接口回传原值。
回归直接使用真实 `CsrfFilter`，分别检查遮罩头通过、原值头/错误值/缺失值拒绝，
以及同一 Cookie 的不同响应仍有不同遮罩。完整 HTTPS 故事另验证真实请求路径。

- [锁定版本的 SPA 配置与头解析](https://github.com/spring-projects/spring-security/blob/7.1.1/config/src/main/java/org/springframework/security/config/annotation/web/configurers/CsrfConfigurer.java#L375)。
- [锁定版本的 XOR 遮罩生成与还原](https://github.com/spring-projects/spring-security/blob/7.1.1/web/src/main/java/org/springframework/security/web/csrf/XorCsrfTokenRequestAttributeHandler.java#L51)。

## 一手依据

登录信息中的网址按OIDC标准保存为文本。框架运行时会把 `iss` 转成 `java.net.URL`，
直接带类型保存会被安全反序列化拒绝。私有会话编码器仅把URL写成文本，保留原有
类型校验；不会把URL、Runtime或File等类型加入恢复白名单。完整对象往返及恶意
类型拒绝在节点实际通过，且专门检查转换不调用URL网络方法。

- [OAuth 安全最佳实践 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)：授权码、PKCE、重定向与令牌保护。
- [Spring Security 7.1.1 登录实现](https://github.com/spring-projects/spring-security/tree/7.1.1/oauth2/oauth2-client)：复用标准协议实现，不自行编写登录协议。
- [Spring Security 7.1.1 跨站请求防护](https://github.com/spring-projects/spring-security/blob/7.1.1/docs/modules/ROOT/pages/servlet/exploits/csrf.adoc)：单页应用的会话变更防护。
- [Spring Boot 4.1 发布说明](https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-4.1-Release-Notes)：当前锁定版本的组件与兼容范围。
