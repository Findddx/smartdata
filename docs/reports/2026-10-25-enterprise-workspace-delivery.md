# 从单机演示走向真实企业协作

日期：2026-10-25。状态：节点上的真实数据库与登录验收已通过，正在核对最终云端结果。当前公开主线仍以
上一轮岛屿工作台为稳定预览；企业协作在 `codex/enterprise-workspace` 分支核验后再合入。

## 本轮解决什么问题

上一轮已能盘点数据、分工、评论和复核，但身份可由同一操作者切换，通用工作区仍
存放在本机文件。已有 PostgreSQL 仓储负责订单履约内核，并未自动覆盖这个工作区。
所以，漂亮的多人工作界面还不能证明真实员工已经能够安全地共同工作。

本轮把这处断点接起来：企业登录核对“这个账号是谁”，成员目录决定“现在能做什么”，
共享数据库保存两人的工作与证据；另一人凭新观察复核，不能靠换角色自己审自己。

## 已经写进程序的能力

| 使用者能做什么 | 程序怎样保证 |
|---|---|
| 用企业账号登录 | OIDC，即标准企业登录协议；登录码与这次请求绑定，令牌留在服务器 |
| 让指定员工加入 | 邀请绑定准确账号编号；企业由部署方固定，网页不能自行填写企业或角色来提权 |
| 调整、暂停、恢复成员 | 每次请求读取当前成员状态，写入时再查授权版本；旧邀请不能恢复被暂停成员 |
| 共同处理有证据的问题 | 来源、扫描、任务、评论和定义历史进入25张独立工作区表，快照正文单独保存 |
| 重启或更换服务实例后继续 | 登录状态进入独立、加密的共享会话表；会话账号不能读业务表，业务账号不能读会话表 |
| 知道谁改了权限与任务 | 同一事务保存审计，记录变更前后角色、状态和版本；历史不能被普通运行账号覆盖 |
| 识别重复和过期请求 | 命令编号与版本在数据库核对；外部调用先登记操作，结果不明时不盲目重发 |

“事务”是一起提交或一起取消的一组数据库操作；“版本”用于发现同事已经修改了记录。
当前仍保留整个工作区的版本检查：两人同时保存可能发生冲突，需要核对后重试，界面
保留草稿。这里没有宣称已能自动合并所有并发编辑。

界面沿用紧凑岛屿、原创标识、图谱和艺术主题；新增登录、等待加入与成员管理。
权限来自服务器，演示切换仅在服务器明确声明本机模式时显示。切换账号或退出时，
查询缓存与迟到响应也必须隔离，不能把上一身份的资料重新放回页面。

## 怎样使用

先看[企业工作区上手](../operations/enterprise-workspace.md)。目前仍需授权运维人员准备
企业账号服务、专用 PostgreSQL 和 HTTPS 证书，尚未做到普通负责人下载后完全零运维。

数据库准备是独立命令 `:runtime-api:prepareEnterpriseDatabase`，只在这个运维进程中使用
迁移凭据。网页服务使用业务和会话两个独立的低权限账号，不自动建表或切换到文件保存。
前端先按锁定依赖构建，再用 `-PbundleConsole=true :runtime-api:bootJar` 合成同源安装包。
同源意味着网页与登录接口使用同一个 HTTPS 地址，减少额外代理和跨站会话配置。

首位负责人须经部署方明确确认。其他员工登录后复制自己的账号编号，由负责人邀请；
没有成员权限时只能看到等待加入状态，不能先进入工作区再靠前端隐藏按钮限制访问。

首次云端证据对应提交 `ec75f530`，见[实际运行](https://github.com/Findddx/smartdata/actions/runs/40222897716)。
其中7项工作区失败来自字段名安全检查遗漏数字，连 `sha256` 这样的正常名称也被拒绝；
已经修复并在第二轮[云端实际运行](https://github.com/Findddx/smartdata/actions/runs/40224962946)
通过全部9项工作区测试，另有20项原内核及6项成员目录测试通过。

修复后的4项字段边界测试，以及3项登录脱敏诊断测试已通过。登录诊断只记录随机审计
编号、受控错误类别和数据库错误码，保持业务正文、令牌、登录码和个人信息不进入日志；
这些线索随后把问题定位到登录状态的保存与恢复，没有因一次空身份响应就猜测修改认证规则。

最后的登录断点也已在节点复现并修复：框架把网址转换成Java地址对象，而原来的安全
保存格式不允许恢复这个对象。现在把网址按标准格式写成文本，保留原有类型限制；
5项完整登录信息往返、网络操作禁止及恶意类型拒绝测试通过，完整HTTPS协作故事也通过。
单元测试曾经通过而真实流程失败，说明验收必须把真实对象形状、过滤器与数据库连起来。

节点[验收摘要与报告指纹](../verification/2026-10-25-enterprise-node.json)记录了实际测试数、
输入版本、两次受控修补、最终关键源码指纹和数据库镜像。全量检查使用固定Java运行环境
`25.0.4.1+1`，合成输入和独立身份协议测试服务；
只使用两核低优先级任务，不使用GPU加速。这里证明工程链路，不证明真实企业身份服务已接入、
真实员工已试用或已达到生产容量。

测试代码不等于已执行的结果；真实数据库使用 PostgreSQL 18，不能以 H2 等简化数据库
代替。登录验收经过发现、公钥、签名、登录跳转、回调和共享会话；不能只在测试里放入
身份对象就说真实认证已通过。真实身份供应商接入还需按具体企业配置单独验收。

在联调前，按锁定版本的框架源码确认并修复了校验码格式不一致的问题：页面取得的是
带遮罩的校验码，请求头也须按同一规则解码。新增5项实际过滤器测试已通过，验证正常
遮罩值可以提交，原始值、缺失值和不匹配值被拒绝；没有降低安全检查来通过测试。

## 仍然保留的边界

- 当前每个企业数据平面固定一家企业。托管平台的多企业选择、舰队管理和控制面尚待接通。
- 企业模式首期只接受获准上传的有界完整JSON快照，使用规则助手；远程API、持续采集、
  真实模型调用、对象存储和履约写动作仍须各自完成生产装配及验收。
- 快照上的“已复核”只表示该观察范围通过了相应规则，不能据此宣称外部店铺、仓库或数据库
  已经修复。不同账号也须由企业确认人员归属，真实双人业务流程仍需试点核实。
- 暂停SmartData成员会阻止后续访问；只在外部账号系统停用员工，不等于已即时撤销本平台
  的所有会话。外部账号系统的即时停用通知尚未接入，默认还有限制闲置与最长登录时间。
- 仍需验证备份恢复、滚动升级、容量与时延，并取得真实业务试点、负责人及审核数据。
  合成输入上的成功不能当作真实企业收益或全平台已经成熟的证明。
